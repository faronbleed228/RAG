# Repository Guidelines

## Состояние и структура проекта

Сейчас в корне есть `README.md` с одним заголовком, `.gitignore` и задание `RAG.md`; исходного кода, тестов, `Makefile` и конфигурации зависимостей пока нет. Считай `RAG.md` источником требований, а не описанием уже реализованных возможностей. По заданию будущая структура включает `src/` (Python-модуль), `pyproject.toml`, `uv.lock`, `data/raw/` (корпус), `data/processed/` (индекс) и `data/datasets/` (вопросы). Не коммить большие данные, веса модели и сгенерированные результаты.

## Разработка и проверки

Проект должен использовать Python 3.10+, `uv` для зависимостей, Python Fire для CLI, `tqdm` для длительных операций и Pydantic для моделей данных между этапами. CLI вызывается как `uv run python -m src <command>`; обязательны `index`, `search`, `search_dataset`, `answer`, `answer_dataset` и `evaluate`. Индексирование, поиск и генерация ответа должны соответствовать форматам и ограничениям из `RAG.md`.

Когда появится `Makefile`, в нём нужны цели `install`, `run`, `debug`, `clean` и `lint`. Цель `lint` должна запускать `flake8 .` и `mypy .` с флагами, указанными в разделе V.2 задания. Сейчас эти команды ещё не настроены: не сообщай, что они прошли, без запуска.

## Стиль и тестирование

Соблюдай `flake8`, добавляй аннотации типов и docstring по PEP 257. Обрабатывай ожидаемые ошибки и закрывай ресурсы через контекстные менеджеры. Проверяй края ввода CLI: пустой запрос, `k=0`, отсутствующий файл и некорректный JSON. Задание рекомендует отдельные тесты на `pytest` или `unittest`, но конкретный фреймворк и порог покрытия пока не выбраны. Для поиска важны точные пути и символьные диапазоны, фрагменты не длиннее 2000 символов, а также recall@5 из `RAG.md`.

## Как помогать мне учиться

По умолчанию действуй как наставник: помоги разделить задачу на небольшие шаги, задай наводящий вопрос и давай подсказки от общей идеи к конкретной. Связывай новые понятия с этапами этого RAG-проекта и объясняй их на коротких примерах. Если я показываю свой код, сначала разбери мой подход, укажи конкретную ошибку или следующий шаг и дай мне возможность исправить её самому. Не пиши готовое решение и не редактируй код вместо меня без явной просьбы. Если я прошу код или правку, выполни просьбу и кратко объясни ключевые решения.

## Коммиты и ревью

В истории пока только `Initial commit`, поэтому устоявшегося формата сообщений нет. Пиши короткие сообщения о сути изменения. В описании PR указывай, что изменилось и какие проверки реально выполнены; для изменений поиска добавляй измерения recall@k, если они доступны.
