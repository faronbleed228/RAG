# Repository Guidelines

## Состояние и структура проекта

Проект находится на этапе индексирования, одиночного поиска и разработки пакетного поиска. Считай `RAG.md` источником требований, а не описанием уже реализованных возможностей. Перед работой сверяй это описание с текущим кодом: пользователь активно меняет проект.

- `src/__main__.py` — CLI на Python Fire; зарегистрированы `index`, `search` и незавершённая `search_dataset`.
- `src/indexing/chunker.py` — модели Pydantic `MinimalSource` и `DataChunk`, разбиение Python через AST и отдельные стратегии для Markdown и текста. Размер чанка по умолчанию — 2000 символов; текущая реализация принимает значения от 10 до 2000.
- `src/indexing/index.py` — сохранение чанков в `chunks.jsonl`, построение и сохранение BM25-индекса через `bm25s`.
- `src/search/search.py` — одиночный поиск: загрузка чанков и индекса, ранжирование, печать путей и символьных диапазонов. Функция пока возвращает `None`, а не список источников. Токенизация корпуса и запроса использует строковые токены (`return_ids=False`).
- `src/search/search_dataset.py` — модели вопросов, `RagDataset` и `MinimalSearchResults`, проверки аргументов и чтение датасета. Пакетный поиск и сохранение результатов пока не завершены; наличие команды в CLI не означает готовность полного сценария.
- `src/answer/answer_data_classes.py` — заготовка; генерация ответа не реализована. Команд `answer`, `answer_dataset` и `evaluate` пока нет.
- `tests/` — тесты на pytest для чанкинга, сохранения индекса, одиночного поиска и CLI; `tests/fixtures/` содержит исходные тексты для граничных случаев.
- В корне есть `Makefile`, `pyproject.toml`, `uv.lock` и `.python-version`. `README.md` пока содержит только заголовок.

Корпус по умолчанию расположен в `data/raw/vllm-0.10.1/`, индекс — в `data/processed/`, вопросы — в `data/datasets/AnsweredQuestions/` и `data/datasets/UnansweredQuestions/`. Большие данные, веса модели и сгенерированные результаты не должны попадать в новые коммиты. В текущем Git уже отслеживаются корпус и индекс; не считай это соответствием требованиям задания и не удаляй их в рамках посторонних правок.

## Форматы и интерфейс

`chunks.jsonl` — внутреннее хранилище чанков; сабджект не задаёт формат хранения индекса. Не путай его с JSON-файлами для проверки: `search_dataset` должна сохранять один объект `StudentSearchResults` с полями `search_results` и `k`, а `answer_dataset` — `StudentSearchResultsAndAnswer`. Модели и поля сверяй с разделом VI.4 задания.

Входной JSON датасета имеет внешний объект `{"rag_questions": [...]}`. Весь документ валидируется моделью `RagDataset`; список вопросов доступен через `.rag_questions`. Передавать весь документ валидатору `list[UnansweredQuestion]` нельзя. Сохраняй исходные `question_id`, чтобы результаты сопоставлялись с вопросами.

Одиночный `search` сейчас выводит источники в терминал; генерация естественно-языкового ответа относится к `answer`. В VI.6 сохранение файла явно требуется для пакетных команд, хотя VI.5 обобщённо говорит о JSON-выводе команд. Учитывай эту неоднозначность при обсуждении требований.

Стандартный сценарий использует индекс из `data/processed/`: выбирать каталог при каждом запуске не нужно. В существующих функциях есть необязательные параметры `input_directory`, `index_directory` или `index_dir`; не делай выбор каталога обязательным. Обязательные аргументы пакетных команд и настраиваемые пути соблюдай по VI.6–VI.7. Для пакетного поиска загружай индекс и чанки один раз на датасет.

## Разработка и проверки

Сабджект требует Python 3.10+, но текущие `pyproject.toml` и `.python-version` настроены на Python 3.12. Используй `uv` для зависимостей, Python Fire для CLI, `tqdm` для длительных операций и Pydantic для моделей данных между этапами. CLI вызывается как `uv run python -m src <command>`; полный обязательный набор команд — `index`, `search`, `search_dataset`, `answer`, `answer_dataset` и `evaluate`. Для генерации по заданию нужна модель `Qwen/Qwen3-0.6B`.

В `Makefile` уже есть цели:

- `make install` — `uv sync`.
- `make run ARGS="..."` — запуск CLI; по умолчанию `ARGS=--help`.
- `make debug ARGS="..."` — запуск CLI через `pdb`.
- `make test` — `uv run python -m pytest tests`; дополнительные параметры передаются через `TEST_ARGS`.
- `make clean` — очистка кешей с исключением `.git`, `.venv` и `data`.
- `make lint` — flake8 и mypy через `uv run --with`, с исключением `data` и `.venv`. У mypy используются обязательные флаги `--warn-return-any --warn-unused-ignores --ignore-missing-imports --disallow-untyped-defs --check-untyped-defs`, а также `--explicit-package-bases`.

Наличие цели или теста не означает, что проверка проходит. Сообщай только результаты реально запущенных проверок. Для изолированных проверок используй небольшой временный корпус и отдельный каталог индекса, как в `tests/conftest.py`; не перезаписывай основной индекс без необходимости. Текущий `BaseChunk.update_path` отклоняет корпус вне корня проекта, поэтому временный корпус создавай внутри проекта, а индекс можно сохранять в `/tmp`.

## Стиль и тестирование

Соблюдай `flake8`, добавляй аннотации типов и docstring по PEP 257. Обрабатывай ожидаемые ошибки и закрывай ресурсы через контекстные менеджеры. CLI должен завершаться с понятным сообщением без необработанного traceback для ожидаемых ошибок; общий обработчик находится в `src/__main__.py`, исключения проекта — в `src/errors.py`.

Проверяй пустые и пробельные запросы и пути, `k=0`, неверный тип `k` (включая `bool`), `k` больше числа чанков, отсутствующие файлы и повреждённый JSON или индекс. Пустую строку пути отклоняй до создания `Path`, поскольку `Path("")` обозначает текущую директорию. Отсутствующий аргумент (`None`) и явно переданный пустой путь — разные случаи.

Используй существующий pytest; порог покрытия не задан. Для чанков проверяй лимит длины, совпадение `source[start:end]` с содержимым и восстановление файла последовательным объединением чанков. Учитывай Unicode, длинные строки, пустые файлы, декораторы и границы Markdown.

Для recall важны точные пути относительно корня проекта (например, `data/raw/vllm-0.10.1/...`) и символьные диапазоны длиной не более 2000. Moulinette сравнивает JSON результатов с эталонным датасетом, а не с `chunks.jsonl`: источник засчитывается при совпадении пути и пересечении диапазонов по порогу IoU 0.05. Требования: recall@5 не ниже 80% для документации и 50% для кода, индексирование не дольше 5 минут, поиск по 200 вопросам не дольше 90 секунд. Эти показатели пока не подтверждены измерениями. Собственная команда `evaluate` нужна для разработки; решение не должно импортировать или вызывать официальную moulinette.

## Как помогать мне учиться

По умолчанию действуй как наставник: помоги разделить задачу на небольшие шаги, задай наводящий вопрос и давай подсказки от общей идеи к конкретной. Связывай новые понятия с этапами этого RAG-проекта и объясняй их на коротких примерах. Если я показываю свой код, сначала разбери мой подход, укажи конкретную ошибку или следующий шаг и дай мне возможность исправить её самому. Не пиши готовое решение и не редактируй код вместо меня без явной просьбы. Если я прошу код или правку, выполни просьбу и кратко объясни ключевые решения.

## Коммиты и ревью

В истории уже есть коммиты по чанкингу, индексированию, обработке ошибок и CLI поиска; сообщения преимущественно короткие, на английском. Пиши короткие сообщения о сути изменения. Сохраняй незакоммиченные изменения пользователя и не включай посторонние файлы в коммит. В описании PR указывай, что изменилось и какие проверки реально выполнены; для изменений поиска добавляй измерения recall@k, если они доступны.
